# Cloud

A workspace connects to one domain: a Cloudflare Worker + R2 bucket + D1
database on the user's own account. Connected = the folder's documents are
backed up and synced on every Mac holding it; publishing is a flag in the
synced manifest, rendered by the worker from the synced files.

- [cloud-worker/README.md](../cloud-worker/README.md) — wire contract: routes, bucket, D1, manifest v6, auth.
- [cloud-publishing.md](cloud-publishing.md) — public pages.
- [cloud-people-agents.md](cloud-people-agents.md) — members, presence, leases, agents, document API, CLI, limits.
- [versioning.md](versioning.md) — history (the cloud mirrors the version store).

## Vocabulary

- **Workspace** — the folder Doklin opens; unit of sync and publishing. Untitled notes are in none.
- **Domain** — a worker's hostname (custom or `workers.dev`). "Backend" here means the app's Rust side, never the worker.
- **Section** — a part of a workspace with its own people: Library (everyone; the bucket's root, space id `""`), a person's My files, and every share. The last two are *spaces* on the domain. Sections are a tree: a share sits in a My files or in another shared folder (`spaces.parent`), never in Library, and **whoever can open the section it sits in can open it**.
- **Share** — a folder, or one document (its markdown, its html, its sidecar), shared where it is with the people picked. Its **owner** is whose My files it is in, in the end. Anyone who can open it reads, edits, renames it and shares it further; only somebody who can open the section it sits in **places** it — moves it, deletes it, restores it. Anyone else leaves it.
- **Engine** — the Rust task syncing a workspace. **Unit** — its sync of one section.
- **Manifest** — a section's one mutable object: every file's path, rev, hash, plus the public map.
- **Key** — worker secret `OWNER_TOKEN`, minted by the app for setup and for each recovery and set on the worker by an agent. Never a sign-in: traded once for a device sign-in as the superadmin. No device keeps it.
- **Superadmin** — the one person who last traded a key, i.e. whoever controls the Cloudflare account. Theirs on every device; no device is special ([cloud-people-agents.md](cloud-people-agents.md) *Credentials*).

## Rules

1. **One domain ⇄ one workspace.** A second bind is `409` → the app offers join, never a second binding. Only the superadmin's wipe frees a domain. A folder whose marker names domain A cannot connect to B.
2. **The engine is the only code that holds a token or talks to the domain.** The frontend never fetches: commands in, events out. It sees a key only to put it in a prompt (`cloud_mint_token`), and a token only to hand it from one command to the next. The worker writes the manifest only for callers with no engine — an agent, a person in a browser — by the same CAS. A browser holds no token either: its sign-in is a cookie no script can read ([cloud-people-agents.md](cloud-people-agents.md) *A browser*). True of the iPhone's screens too: Swift calls the same commands, and the token it hands from `cloud_redeem` to `cloud_join` is kept by the engine, in the Keychain (`Host::secrets`).
3. **The manifest is the only truth about what is public.** The frontend's view is `CloudStatus.public`; no `localStorage` registry.
4. **A public page is a rendering of synced files.** The worker stores no page content.
5. **Disk is the source of truth for content.** Merge, never clobber; overlaps become a conflict copy beside the file; deletions go to the macOS Trash (`Host::trash`). The iPhone has none: a deletion there is outright, and the version store keeps what went.
6. **A skewed app/worker refuses legibly and never corrupts** (see Worker versions).
7. **No accounts, dashboard or terminal for the user.** Setup and teardown are prompts for an agent running wrangler; the update is a script.
8. **The worker imports only pure `src/` modules** — nothing touching Tauri or React.
9. **The engine crate (`engine/`) knows nothing of the app around it**: no Tauri, no Swift, no `cfg` on which app. What differs is said once in `Setup` and asked through `Host` (`engine/src/host.rs`). A command is written once, in the engine; each app only reaches it. The browser version builds in no engine and answers the few commands it has (the status, a page's link, publishing, the beat) in TypeScript (`src/web/`): each says which engine function it follows, **change both**.
10. **Only documents sync**: markdown, html and each document's comments (`<stem>.meta.jsonl`), and a folder's `boards.json` — `syncs` (`engine/src/lib.rs` ⇄ `cloud-worker/src/layout.ts`, **change both**). Everything else stays on its device: the scan, the edit bus, the version store and the export never see it, and the worker refuses it. What means *a document* asks `is_document` instead (sharing one file, its link, its name, its files by stem, publishing): a document called `boards.md` never takes a folder's `boards.json` along.
11. **Only a client that does not send protects the account's day** (Workers Free: 100,000 requests a day for the whole account, reset 00:00 UTC; past it every request gets Cloudflare's 1027 page). A request the worker refuses is already counted. So the engine and the CLI pace themselves; the worker's `[[ratelimits]]` only catch loops.
12. **The OS decides which certificates to trust.** Every HTTPS client the apps build comes from `engine/src/https.rs`: Apple's own check on a Mac and an iPhone, so a CA a company installs works and one Apple distrusts does not. No roots are bundled. A refused certificate is `Offline`, as a Wi-Fi sign-in page is. A Mac's proxy settings are not read: reqwest's `system-proxy` ignores the bypass list, so it would send loopback (the PDF engine's DevTools) through the proxy.

## Engine ⇄ frontend contract

- Commands: `cloud_*` in `engine/src/cloud/mod.rs`, each with a Tauri wrapper in `src-tauri/src/cloud.rs` and an arm in `engine/src/command.rs` (a test fails without the arm), and a method of `Cloud` (`src/backend.ts`) that `src/mac/backend.ts` answers with it. Events (`status.rs`): `cloud-status` (whole `CloudStatus[]` on every change; disconnect = array without it), `cloud-applied`, `cloud-conflict`, `cloud-pending-deletes`, `cloud-pending-adds`, `cloud-progress`, `cloud-address-taken`, `cloud-space-left` (something shared was deleted from this device), `cloud-space-moved` (something shared is somewhere else on this device, or called something else: what the app has open from it follows), `cloud-removed` (this Mac's copy was deleted: [cloud-people-agents.md](cloud-people-agents.md) *Losing access*).
- Every path in a status or an event is workspace-relative, whichever section it is in (`Library/x.md`, `My files/x.md`); a lease's `path` is that, lowercased. A share's `path` is its item: a folder, or a document without its extension. A section's whole folder is its name: publishing `Library` (a folder) publishes the shared section, and its page's `path` is `Library`; `""` is no section. Pending adds are grouped two levels below a section's folder (`Library` for one directly in it).
- Payload types: `status.rs` serde structs ⇄ `src/cloud.ts` ⇄ `ios/DoklinKit/Sources/DoklinKit/Engine/Payloads.swift`. **Change all three.**
- `CloudStatus` is the frontend's whole cloud model; surfaces derive from it. Phases: `idle syncing offline paused pending-deletes pending-adds revoked worker-outdated app-outdated limited error`. `usage` says what this device spent today and the mode it puts sync in (*Pacing*); its sentences are the surfaces', from `usage`, except `limited`'s, which is the engine's `error`.
- The Mac reports window focus from Rust (`WindowEvent::Focused` → `cloud_set_focus`, the window's folder from the registry); the iPhone from `woke`/`settle`. No frontend code is involved.
- A status `by` is already a name (resolved via `/api/meta` `people`).

## Engine behaviour

**Inputs** (each wakes a cycle or a poll):
- Edit bus: every app write command ends with `edits::touched(&app, &path)` (→ engine and versioner). A new write command must too. Settles 1.5 s (`TOUCH_SETTLE`). `scan::rel_for_touch` drops hidden segments, the engine's temp files and files that do not sync.
- A move the app makes is told as well, before both ends are touched: `edits::moved` in `move_path` (the Mac's every rename and move), `Workspace.moved` on the iPhone (the `moved` command) → `Core::moved` → `EngineCmd::Moved`. A new move command must too. A file or a folder; dropped when the two ends are not in one workspace (`scan::rel_in_scan`). Kept, like the touches, until a pass goes through (`Engine::app_moves`).
- Watcher (`notify`): settles 5 s (`FS_SETTLE`); optional — the other inputs still sync.
- Poll by attention (`Engine::poll_gap`): every 15 s (`POLL_INTERVAL`) while a window of the workspace is focused and used in the last 5 min; 60 s unfocused or idle 5–30 min; 5 min idle longer; a focus after a quiet spell polls at once. `GET /api/poll`, or `POST` when a presence beat is owed (at most every 45 s, `PRESENCE_BEAT`); the beat's `ttl` is 2.5 × the gap to the next one (90 s–15 min), so an idle device stays listed. A new etag — the shared manifest's or a space's, all in the one answer — triggers a pass, and so does a poll that gets through while the phase is `offline`.
- Commands: `EngineCmd` in `engine.rs`.
- Hints say *when*, never *what*: the cycle always walks the whole tree and decides from content. A move the app made is the one that says *what*, and only where the folder agrees.

**Sections** (`engine.rs`, `space.rs`):
- On disk three folders sit side by side, found in any case (`space::top`): `Library/` (`LIBRARY_DIR` ⇄ `LIBRARY_FOLDER` in `layout.ts` ⇄ `src/cloud.ts` ⇄ `TreeModel.libraryFolder` in the iPhone's `Tree.swift`: **change all four**), `My files/` and `Shared with me/` (`MY_FILES_DIR`, `SHARED_DIR`, the same four places). Hidden entries at the root are the folder's, not a section's.
- **Anything else at the root is in no section**: it stays on this device and syncs nowhere (`Engine::place` answers none, so the edit bus drops its touch). So is the root itself, `Shared with me` itself, and what is under it that nobody shared.
- Inside Library a folder is called anything: a section's name is its own only at the root.
- **`Library/` missing** (deleted, or renamed in Finder — it is then a stray) is a section to bring back whole, never a folder whose files were deleted (`Engine::mend_library`): Library's sync state is dropped and everything downloads again. Never tombstones. Something that is not a folder under that name is phase `error` with a sentence, and nothing is dropped.
- Manifests, tombstones' `to`, presence, leases and every wire path stay relative to their section.
- **Where a section is on a device** (`reconcile_spaces`, the sections things sit in before what sits in them): My files at `My files/`; a share whose parent this person can open at that parent's folder + `mounts[id].dir` (the parent's manifest; no entry is its top); any other share at the top of `Shared with me/`. One found anywhere else is moved there. A browser places the same way (`settle`, `src/web/workspace.ts`): **change both**.
- **A unit's reach** (`Reach`): its folder less the shares inside it — the folders that are other units' roots, the documents other units hold. A shared document's unit has the folder the document sits in as its root, and reaches that document's files alone. `Engine::place` answers the deepest unit. Everything that walks a section walks by its reach: the scan, and the version store (`SectionTable`, [versioning.md](versioning.md)).
- A shared folder is a space by its marker, `<folder>/.doklin/space.json` `{wsId, space, name, dir}`; `name` and `dir` are what this device last matched it to, which tells a rename or a move made here from one made elsewhere. The marker travels with the folder, and a folder without one is never deleted. A shared document has none: `spaces/<id>/doc.json` in the state says which files are it, and its parent's `mounts[id].was` finds it again after a reinstall.
- Two folders that say they are one space are a folder and a copy made outside the app: the one where its marker says is the space, and the other stops saying so (`space::held`). The app's own copy never carries a marker (`copy_recursive`).
- **One rule where a name is taken** (`free_name` ⇄ `settle`, **change both**): its name; its name and its owner's; then a number. A name here that is one of those is not a rename (`names_item`). A shared document's stored name and its name on this device are two (`DocName`).
- **Making a share** (`Engine::share`): the id is minted here (`s-<8 hex>`), the intent written down (`pending-share.json`), then `POST /api/spaces {id, kind, name, parent, dir, was, members}`; the worker writes the parent's `mounts` entry in that call. Nothing moves on disk: the next pass reads the item's files as moved from the parent's unit to the new one. The same id from its maker again is the same share, so a quit in the middle is finished at the next start. `was` is the item's path in its parent when it was shared (a document's without its extension): another device of its owner's finds its files there and downloads none. It refuses while `spaces` is `None`: adding to a list the domain has not given would make everything missing from it look left. Something shared already gets the people added instead.
- **A share's item gone from disk is never a deletion**: it comes back whole. A shared document's file that is missing, and that the app did not say it deleted (`touched`), is followed by its content among its parent's files nobody has synced, else the document comes back (`follow_documents`). Only `cloud_share_delete` deletes a share.
- **A share's item the app renamed or moved is still that share where it went**: the pass heeds the app's moves first (`heed_moves`, over `Engine::app_moves`, *Inputs*), and what it renames of a shared document's files goes to that unit's scan with them (`Unit::renamed`). Inside its parent, the parent's `mounts` says where (`queue_mount` — the one thing a device writes there); in another section, `PATCH {parent, dir}`, and that section's people open it too; in Library it is everyone's, so the share ends (`ending`: its files become Library's, then it is erased). A move the domain refuses, or cannot hear, puts the item back. Outside the app a shared folder is followed by its marker and a shared document by its content.
- Somebody who cannot open a share's parent is told nothing of where it sits (`parent: null`), and has it pinned under `Shared with me/`: moved by hand it comes back.
- A share no longer listed is deleted from this device outright, with its sync state and version store; on the device that deleted it for everyone it goes to the Trash. Either way `cloud-space-left`. Never a My files: a list without one is mended (`PUT /api/spaces/private`).
- A file another device moved to a section this one has not heard of waits for a poll (`asked_about`): it may be a share its own person made a moment ago. A poll that does not list that section is what deletes the copy.
- `spaces: null` in a poll changes nothing. A space's routes answering `404` stop that unit until the next poll says whether its person can still open it.
- A conflict copy of a shared document cannot join its section: it is made beside the document for somebody who can open that folder, and in their My files for anybody else (`Ctx::copies_in`).
- `CloudStatus.spaces` is drawn from the units, so a device that started offline still lists what it holds. A deleted share this person can restore is listed with `deletedAt` and no path.

**The move into Library** (`layout.rs`), what connecting a folder does to its files:
- The marker's `layout`: absent (not moved yet), `"moving"`, `"my-files"`. The steps and how each is resumed after a crash are in `layout.rs`'s header. Renames only, never copies.
- When: `cloud_connect` (after the marker, before `seed_upload`, which uploads `Library/`) and `cloud_resume` (a folder whose files are not in Library yet). Both stop the root's versioner once the move has begun (`versions::release_root`) and reconcile after. The Mac moves what it stores about the folder's paths with it (*Sections in the app*).
- **A folder that holds something called `Library` at its top does not move** until that is renamed (`layout::begin`), and `cloud_connect` refuses it before the domain is bound: it would be taken for the section.
- **No engine syncs a folder that is not in the layout** (`layout::ready`, checked at the start of every pass and of `reconcile_spaces`): no marker, an unfinished move, or a layout another build wrote is phase `error` with a sentence. A connected folder whose files are not in Library is disconnected and resumed, which moves them.
- **Traps.** Never move while an engine or a watcher runs for the root: with Library's unit at the root, `x` → `Library/x` reads as a move and every device follows it. Never point Library's unit at `Library/` before every file is in it: a partly moved tree reads as deletions. A build that does not know a folder's `layout` refuses it, which is why the name changes whenever the layout does.
- **ONE-TIME** (`layout::from_library`, deleted once every device has run it): a folder as the build before sharing in place left it (`layout: "library"`, `Private/`, `Restricted/<folder>/`) is brought to this layout as the app starts, before any engine, watcher or versioner runs on it — each section's version store re-keyed first, then `Private/` → `My files/` and each `Restricted/<folder>/` → `Shared with me/<folder>/`. Refused with a sentence, nothing moved, while something else at the root has one of the new names. The first poll then moves a folder its own person shares to where it sits in their My files. `cloud_layout_moved` names the roots it did, and what an app stores about paths under them follows (`moved_rel` ⇄ `fromLibraryLayout` in `src/cloud.ts` ⇄ the iPhone's: **change all three**).

**Sections in the app** (`Sidebar.tsx`, `App.tsx`, `ShareDialog.tsx`, `src/cloud.ts`):
- `placeOf(cloud, rel)` is the one answer to "who can open this path": the deepest section that holds it, a shared document's before the folder it sits in. `nowhere` = the root, anything at it outside the three folders, `Shared with me` itself and what nobody shared under it. `audienceOf` is who that is; `widerAudience` whether a move adds anybody. The iPhone asks the same (`Sections`): **change both**.
- The tree of a connected workspace is three headings — Library, My files, Shared with me — and never says "Workspace". Each heading stands for its folder (found however the disk spells it) and is never a row of its own. What is shared stays a row where it is, marked. Strays follow under "In no section", each marked as not synced. A folder that is not connected is one "Files" list.
- Whatever would land at a connected root lands in Library: nothing selected, ⌘V, saving an untitled note. The root and `Shared with me` are never a drop or a paste target, and nothing is made straight under `Shared with me`.
- Empty space in the tree is the list it is in (`sectionAt`): beside its rows, before the next heading's line, and under the last list. A right-click or a drop there acts on that list; under Shared with me and "In no section" nothing is made, so there is no menu. A heading's buttons make in their own list, in the selected folder only when the selection is in that list.
- The Library heading carries Library's own items: *Library history…*, *Recently deleted*, *Publish Library…* (a publish of `<root>/Library`). Library's history is Library's store (`libraryDirOf`); every versions command for it names `<root>/Library`.
- **One Share dialog** (`ShareDialog`), for a folder or a document in My files or in something shared, shared yet or not; a document's is also the button above it (`ShareChip`). Nothing in Library is shared on its own, and nothing in no section. The Live chip shows only for a file in a section; *Copy link*, *Copy path* and *Share…* are never offered on `nowhere`.
- *Copy path* (`agentPath`) is the path an agent's `doklin` takes, worked out locally: the section spelled as the worker spells it (`SECTION_DIRS` ⇄ `agentPlace.ts`, **change both**), a folder ending in `/`, a document without its extension. No domain: an agent's `doklin` already has it. `My files/…` is the agent's own person's.
- Around `cloud_connect`/`cloud_resume`, once the marker says `layout: "my-files"` (`LAYOUT_NOW`), what the app stores about the folder's paths follows by the move's rule (`toLibraryLayout`): the open tabs (autosaves flushed first), `doklin:session` and the open folders of `doklin:sidebar-tree`.
- A move that lets more people open something is confirmed first (`confirmMove`; "Move … to Library?"), and so is one that takes something shared into Library, where it stops being shared on its own: every drag and every cut-paste goes through it. So is a move into `nowhere`, which takes a file off every other device. Any other move that narrows is not asked about.
- What is shared with this person and is not theirs to place (`placed: false`) is not dragged or cut: it is copied into My files, or left. **Deleting a share is never a trip to the Trash** (`deleteShare`): whoever places it deletes it for everyone, asked first and naming who loses it, and a folder that holds shares is not trashed around them. It is kept thirty days, and restored from the notice or from the *Recently deleted* of the section it sat in — which a browser has too, for shares alone.
- `cloud-space-moved` repoints the open tabs and the tree's open folders (`followSpaceMoved`); a rename or a move the app made itself repoints before it asks the backend.

**A pass** (`Engine::pass`): survey every unit's folder (stat only, no request), then cycle the units that changed, were poked (a queued page, a confirmed deletion), owe bulk work, or that the poll said moved. *Sync now* and first contact cycle all. With several units in a pass every manifest is fetched before any is applied.

**Pacing** (`pace.rs`; the numbers are the worker's, `limits` in `/api/meta` and every poll, per the plan setting — the engine has none of its own):
- Every request with a bearer is counted in `HttpRemote::auth`, per UTC day, in `<state_dir>/usage.json`; every 15 min one carries `x-doklin-used`, and the poll's `limits.fleetToday` is everyone's sum.
- Express lane: polls, manifest reads/writes, and a cycle's transfers while ≤ 50 (`EXPRESS`). Past that, the bulk lane: a batch (100 files / 8 MB) a cycle from a token bucket (200, refilling at `bulkPerSecond`); the app's own edits (the edit bus) always go express. Downloads too: what a cycle cannot take is `owed` (persisted), never pushed over or read as deleted until it arrives. The mirror draws on the same bucket.
- Modes: `bulk-waits` (this device past `deviceBulk`, liftable for the day by `cloud_lift_wait`; or everyone past `fleetBulkWaits`, not liftable) — bulk waits for 00:00 UTC; `slow` (past `deviceCeiling` or `fleetSlow`) — no bulk, a poll and a pass a minute at most.
- A worker whose `/api/meta` carries no `limits` predates them: `worker-outdated` until it is updated.
- A connect or a join is a person's own act and is not paced.

**The retry clock** (`Engine::clock`): a failed pass, poll or probe pushes the next try out 15 s, 30 s, 1, 2, 5, then 10 min (±20 %); a success resets it; a touch during it waits for it; a command from the person does not. `429` (`RemoteError::Slowed`) waits at least its `Retry-After` and leaves the phase, with "The domain asked this Mac to slow down." Cloudflare's 1027 page (`RemoteError::DailyLimit`, recognised by a non-JSON body naming 1027): phase `limited`, nothing sent but a probe every 30 min until 00:00 UTC plus up to 10 min.

**A move between sections:**
- Here (`pair_moves`): a file gone from one unit and new in another with the same name and hash, or one the app said it moved there (`said_between`). Sharing something is this move, for every file of it at once, with nothing moving on disk. The unit it went to cycles first; the source tombstone carries `to` and is written only once the destination holds the file; it never counts toward the mass-delete valve.
- Its public page follows (`carry_pages`): a Remove in the source, a Put in the destination that waits for it (`Ctx::releasing`).
- Elsewhere (`relocate`, a tombstone with `to`): a Mac in that section moves its copy there — adopted by hash, nothing downloaded; an unsynced edit carries on when it was made from exactly what the destination holds, else lands as a conflict copy. A Mac not in it deletes the copy outright (not the Trash) and prunes the emptied folders.

**The cycle** (`Unit::cycle_inner`), one section's:
1. fetch the manifest since our etag;
2. `apply_remote`: downloads, renames, tombstoned deletions to the Trash; three-way merge (`merge.rs`, diffy) where both sides moved; conflict copy `Name (conflict — Alice, Jul 11 14.32).md` on overlap, binary content or no base. A sidecar is merged by its records, never conflicts and never gets a copy (`engine/src/sidecar.rs` ⇄ `mergeMeta` in `src/web/merge.ts`, **change both**; `comments-fixture.json`'s `mergeMeta` holds them alike). So is a folder's `boards.json`, by its `tag`, each card and each key a newer app wrote (`engine/src/boards.rs` ⇄ `mergeBoards`, **change both**; `boards-fixture.json`'s `merge`); when either side is no board this app reads, theirs is kept as it came. When both sides file one link destination under two different files, the one whose file is in any section's manifest wins, else the lowest id. A document's conflict copy gets a copy of its sidecar, made once the pass is done, so it holds both sides' records. Identical bytes on both sides are adopted as synced, never merged. A rename that comes with an edit moves the copy here to the new name first, then replaces it there, or merges an edit made here into it;
3. `scan_local` + `stage_local`. A file gone from its recorded path is, in order: where the app said it moved it, when an unknown file is there (`Ctx::app_moves`, followed in order, a folder's covering what is in it) — one revision that moves it, and edits it if the bytes differ, and a `pending_new` id goes along too; a new file with the same bytes (a move); else deleted. Mass-delete valve: > 30 % of files and ≥ 5 gone in one scan → hold, phase `pending-deletes`, wait for `cloud_confirm_deletes`. Many-new-documents valve (`Engine::weigh_new`, from the surveys, across units): `manyNew` (200) or more new documents in one pass — not renames, not moves between sections — are held, phase `pending-adds`, `cloud-pending-adds` once; `cloud_confirm_adds {sync: true}` sends them (and lifts this device's bulk wait for the day), `false` leaves them until more arrive or *Sync now*. Held in memory, found again after a restart;
4. `build_manifest` + `fold_public` + `fold_tags`; a manifest of an older format is written again even with nothing else to say, so the worker's own writes (which take only this one) can change it;
5. upload blobs, then CAS the manifest; a lost race refetches and redoes, 4 attempts. A new file's id is written down before its bytes go (`pending_new`) and each upload once it lands (`uploaded`, 12 h), so a lost race, a batch, a quit or a crash sends nothing twice and leaves nothing under an id no manifest names.

**Traps.**
- Leaving a manifest without a tombstone is a deletion (`apply_remote`). So anything a rule takes out of the manifests (the md + html rule) leaves every device's state first (`forget_out_of_scope`, on load), and every device updates before the worker.
- A cycle that holds bulk work leaves `Unit::owes`; the task comes back for it when the bucket holds a batch (`bulk_due`), or at the reset while bulk waits.
- Every fallible step lives in `cycle_inner` so every exit funnels through `pass`'s one status report; a `?` in `pass` skips offline/revoked reporting.
- `409 {taken}` on a manifest (`RemoteError::Taken`): the queued page is dropped, `cloud-address-taken` says so, the rest of the cycle goes again.
- **The tag list** is the shared manifest's `tags` (`engine/src/cloud/tags.rs`). `cloud_set_tag {root, at, def}` / `cloud_remove_tag {root, name}` queue a `TagOp` in Library's unit's `tag_ops`, in order, refused in a sentence when the list after it would break the worker's rules (a refused manifest stops sync); the status's `tags` is the list with them made (`effective_tags`), and each cycle folds them over the list as the remote has it (`folded`, ⇄ `withTag`/`withoutTag` in `src/tags.ts`, **change both**): the later change of one tag wins. One that would overfill the list is passed over. Nothing here renames a note.
- A missing root (unmounted, renamed) touches nothing: phase `error`.
- An app's move is a tip, never taken on trust: the scan checks it against the folder. A rename with an edit made outside the app (Finder, git, another editor) is still a deletion and a new document — links, *Copy link* and a published page stay with the deleted id.
- After a merge the stored disk snapshot is left stale on purpose so the next scan re-hashes and pushes the merged bytes. Refreshing it silently drops the push.
- Otherwise a synced file's snapshot is the one that belongs to the bytes its hash is of: the scan's, taken before they were read (`StagedPush::seen`), or the file as written (what `write_atomic` answers). A stat taken after an upload or a download can be of a save made meanwhile, which then reads as synced and stays on that device.
- Tombstones expire after 30 days: `TOMBSTONE_TTL_MS` in `engine.rs` ⇄ `commit.ts`. **Change both.** A move keeps `mtime` in both (`staged.moves` ⇄ `Tx.move`).
- No device deletes a stored copy (`blobs/<fid>/<hash>`): the worker's daily sweep does (`cloud-worker/src/sweep.ts`, a cron trigger), taking every copy its section's manifest doesn't name once it is a day old (`SWEEP_MIN_AGE_MS`). A push uploads before its manifest write, so `UPLOADED_TTL_MS` (12 h) stays inside that day — **change both**. A re-upload of a stored copy's own bytes stores it again, so a file back to an old version restarts that copy's day. Trap: a copy named in the second between a sweep's listing and its delete is still lost; a download of it 404s until the file's next edit.
- `426` on PUT → `worker-outdated`: sync pauses, probing `/api/meta` each poll until a newer worker answers.
- `410` on any route → `app-outdated` (`RemoteError::TooOld`, the worker's sentence in `error`): this app is older than the domain answers (*Mandatory releases*, [release.md](release.md)). Sync stops, probing `/api/meta` on the poll and retry clocks until it is answered; the app covers its windows meanwhile. The update restarts the app, so nothing waits for the probe.
- `by` is a member id (`MEMBER_ID_RE`) or an agent id (`AGENT_ID_RE`), both `layout.ts`. An unknown id refetches the directory at most every 5 min (`DIRECTORY_MIN_GAP`); an id it cannot name shows as it stands.

## Links (`link.rs`, `mod.rs`)

*Copy link* gives a link that opens a document in Doklin for anybody who can see it, wherever it is clicked (only documents sync, so only they have one): `https://doklin.cc/open#d=<domain>&w=<wsId>&s=<space id>&f=<file id>` (`s` absent for the shared workspace).

- **Everything is after the `#`**, which no browser sends to a server: doklin.cc, its logs and a chat app's preview bot never learn the workspace or the page. doklin.cc serves one static page for every link (`site/public/open.html`) and stores nothing.
- **Ids, never a path or a title**: a rename or a move keeps the link. A file keeps its id when it moves to another section — the engine's move (`moved_in`, `unit.rs`) and the worker's (`land`, `changes.ts`): **change both** — so an id is looked for in every section this person holds, the link's `s` first (`Engine::follow`, `pathOfFile` in `src/web/workspace.ts`, `getFind`: **change all three**). While a move is half done one id is in two sections: `s` wins, else the lowest section id. A section that already holds a file by that id gives the arrival a new one.
- **An address, never access.** Being in that section is what opens it; a link never carries a code. A space this person cannot open, a deleted file and one that never was are one answer, so something shared is never told apart from nothing.
- `cloud_link` (absolute path → `{url, who}`) asks the engine for the file's section and id; a file with no id yet waits one pass. `cloud_follow_link` (link → absolute path) finds the workspace by `wsId` in `cloud.json` and the file in that section's synced state, offline; one not here yet waits one poll. Same domain, other `wsId` = the domain was set up again. `cloud_link_target` (link → `{domain, wsId, root}`) reads only the link and `cloud.json`: which workspace it is in, and whether this device holds it.
- **A link from one note to another is an ordinary relative markdown link**; its note's sidecar files the id of the file it means, one record per destination (`{"t":"link","id":<destination, decoded and folded>,"file":<fid>}`, `src/metaFile.ts`). A link with a record opens the file with that id in any section, never the one at its path, which may be another person's; one without goes by its path. The rules (the key, resolving, the words a named link shows, what a save writes) are `src/docLinks.ts`'s, ported for the iPhone's reader (`Markdown/Links.swift`) and held to `verify-harness/links-fixture.json`: **change both**. The worker uses the module itself for agents and public pages (`agentLinks.ts`, `pages.ts`). Who can open a document is one sentence in three places: `linked` (`engine.rs`), `linkTo` (`src/web/address.ts`) and `whoCanOpen` (`src/docLinks.ts`), **change all three**.
- `cloud_documents` (`{root}` → every document on this device, every section, with its file id; null for a folder that doesn't sync, whose tree the app lists) is what links are resolved against, read off the synced state and the folders, offline. A note's html rendition is part of the note (`documents_of` ⇄ `documentsOf`, **change both**). `WorkspaceDocument` in `status.rs` ⇄ `src/docLinks.ts` ⇄ `Payloads.swift`: **change all three**.
- `cloud_recent` (`{root, limit}` → `{files, people, me}`) is what changed lately, read off each section's last applied manifest (`mtime`, `by`, `rev`, `hash`) and the folder — a file changed here since it last synced is this device's, unsynced (`hash` null); a move keeps `mtime` — with the directory beside it. It asks the domain nothing. `RecentFiles` in `status.rs` ⇄ `Payloads.swift` ⇄ `src/cloud.ts`: **change all three**.
- How a link reaches an app: an iPhone opens it straight from doklin.cc (`ios/Doklin.entitlements` + `site/public/.well-known/apple-app-site-association`); anything else gets the page, which hands it on as `doklin://open#…` (the scheme in `src-tauri/Info.plist`, `ios/Info.plist`) — at once on a Mac, on a tap elsewhere. A click on one inside a note never leaves the app (`open_external`, `src-tauri/src/links.rs`; `Workspaces.isPageLink` on the iPhone). `doklin` takes one wherever a document is named (`GET find`), and `doklin info` gives one.
- On a computer the page also offers the browser version, `https://<d>/app#w=…&s=…&f=…` (`takeLink`, `src/web/address.ts`): beside the app on a Mac, the one button anywhere else. **doklin.cc never sends anybody to a domain they did not choose on a page that names it**: a first visit waits for a click, and only a domain ticked *Always* (`browser:<domain>` in doklin.cc's `localStorage`) is gone to without one. A page that skips itself is never in the browser's history, so Back cannot undo that: `doklin.cc/open` with no link after it is where it is undone. `d` must be `is_domain` (`isDomain` in `open.html`: **change both**) or the link is cut short.
- A phone or a tablet is never offered the browser version, whatever was ticked: an iPhone and an iPad keep the app's button, anything else is told to use a computer. What counts as one is `src/web/gate.js`'s, said again in `open.html`: **change both** (`link.rs`'s tests hold the two together).
- `doklin://` only ever navigates: any web page can fire it.
- The address, scheme and keys are said in `link.rs`, `open.html`, `src/pageLink.ts`, both `Info.plist`s, the entitlements, `cli/src/link.rs` and `Workspaces.isPageLink`; the association file names the app as the Xcode project does. `link.rs`'s tests hold every one of them to it: **change all of them together.**

## Flows (`flows.rs`, `mod.rs`)

- **Connect**: name + email asked first → mint key → setup prompt → agent prints `ENDPOINT: https://…` → `cloud_probe` (with the key) → `cloud_recover` trades it for this Mac's sign-in → `cloud_connect` binds with that, writes the marker, moves the folder's files into `Library/` (hidden ones stay), uploads `Library/`, writes `cloud.json`, spawns the engine.
- **Recover** (every device lost): address + name + email → mint key → recovery prompt (`secret put OWNER_TOKEN --name <worker>`, nothing else) → probe → `cloud_recover` → `cloud_join` or `cloud_resume`. Whoever recovers is the superadmin from then on.
- **A key works once** (`spent_keys`): a step after the trade that fails is retried with the token it bought, never the key. A lost key costs nothing — the next recovery mints another, and no device syncs on one.
- **Already bound** (probe shows a workspace): *Download it* (`cloud_join` into `~/Doklin/<name>/Library/`, made even when the workspace is empty; the marker says `layout: "my-files"`) or, when the open folder's marker has that `wsId`, *Resume* (`cloud_resume`). Never "bind anyway".
- **Resume**: the move first, for a folder whose files are not in Library yet; then empty engine state; `stage_local` adopts remote fileIds by path, identical bytes count as synced, merges own the rest (reinstall, restored folder).
- **Join** (a line: an invite, or a device code from another device of the person's): `cloud_redeem` → `cloud_join`, or `cloud_resume` when the open folder's marker has that `wsId`.
- **Never trade for a domain this device holds.** One copy a device per domain, and every step after a trade refuses a second, so `cloud_redeem` and `cloud_recover` refuse first and what was to be spent still works. The wizard asks `cloud_held` before it trades: a copy that syncs is opened; one that has stopped (`revoked`, or its folder gone) is disconnected, then the trade goes on.
- **Disconnect**: stop the engine, end this Mac's sign-in, drop the `cloud.json` entry and state; folder, marker and cloud stay.
- **Wipe** (`cloud_wipe`, superadmin): erase via the worker, then disconnect **including the marker**, so nothing re-uploads into the freed domain; then the teardown prompt.

## Local files

- `<app_data_dir>/cloud.json`: `{version, device: {id, name}, workspaces: [{root, domain, endpoint, wsId, name, token}]}`. One entry per root and per domain; parsed by shape (malformed = nothing connected; an entry with no token = not connected). It is read and written only by `read_cloud_file`/`write_cloud_file` (`cloud/config.rs`).
- Where the token lives: in that entry on a Mac. An app whose `Host::secrets` keeps sign-ins (the iPhone: its Keychain, by `wsId`, this device only, never in a backup) gets each token there and finds `token: ""` in the file; a workspace dropped from the file has its kept sign-in deleted with it. A sign-in the keeper cannot read just now leaves that entry out of the engine and writes it back untouched. The phone keeps its engine files out of backups, so a restored phone has no device id or entries either, and joins again as a new device.
- `<root>/.doklin/cloud.json`: the marker `{domain, wsId, layout}` (`layout`: *The move into Library*). Never a secret (a copied folder must not carry a credential). Hidden, so tree walk, search and scan skip it. A marker with no `cloud.json` entry → offer *Resume*.
- `<app_data_dir>/cloud/<wsId>/state.json` + `base/`: last applied manifest and etag, per-file synced state, queued public ops, tag changes and mount moves; merge bases. Each space's are under `spaces/<spaceId>/` in it, with `doc.json` for a shared document (the folder it is in, its name here and as stored) and an empty `ending` while a share moved into Library hands its files over. `pending-share.json` is a share this device was making when it last stopped.
- `<folder>/.doklin/space.json`: a shared folder's marker, and My files' (*Sections*). No secret.

## Worker versions and updates

- `cloud-worker/src/version.ts` is the one source of `WORKER_VERSION`, `MANIFEST_VERSION`, `COMPATIBILITY_DATE`, and of `MINIMUM_APP` and `MINIMUM_IOS`, which only `release.yml` writes (*Mandatory releases*, [release.md](release.md)). Parsed, never copied, by `engine/build.rs`, `vite.config.ts` (`virtual:cloud-worker-version`) and the bundle script: keep the one-line shape `/^export const WORKER_VERSION = (\d+);$/m`.
- **Bump `WORKER_VERSION` for every wire change and any change to how a public page looks** (renderer, theme, tokens, fonts). It drives the update badge; without it deployed domains never update.
- `WORKER_VERSION` is the one thing read off a worker about what it does: no feature list, nothing gated on one. The engine, app and CLI expect every route and field of the version they were built with.
- Neither side must work with the other's next release; a skewed pair must say so (badge, `worker-outdated`, `426`) and never corrupt. So retired routes and fields are deleted, not kept.
- Move `COMPATIBILITY_DATE` only on purpose: it changes every new deploy's runtime.
- Bundle < 3 MB gzipped (the script fails past it). What public pages ask for — fonts, icons, the flowchart module — is not in it: the script writes it to `doklin-cloud-web/` beside the worker, which Cloudflare serves as static assets. The checked-in `cloud-worker/src/assets.ts` says `WEB_TAG = "dev"`; the bundle script splices in the build's tag (the flowchart module's hash).
- **Update** = `scripts/doklin-cloud-update.sh <endpoint>` (release asset; `updateCommands`). Names from the endpoint (`deploymentNames`); confirms worker, bucket and D1 database exist first (deploying a missing name creates a second worker) and creates nothing; done when unauthenticated `/api/meta` answers `401`. Overrides `WORKER_NAME=`, `BUCKET_NAME=`, `D1_NAME=`. No secret.
- **Setup prompt** checks names are free first (a same-name deploy silently replaces a worker) and that `/api/meta`'s `d1` is a number. **Teardown** runs after the wipe, never forces a non-empty bucket. `wrangler.toml` is never committed. `verify-harness/cloudprompts.test.mjs` pins prompts and script to the naming rule and compatibility date.
