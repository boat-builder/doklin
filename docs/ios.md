# iOS app

`ios/`: a native iPhone and iPad app. Xcode 26 or later, iOS 26.1 or later, Apple Silicon. It is a **device** of its person's, like a Mac: it holds every workspace it joined as files of its own and syncs them in the background with the Mac's own engine (`engine/`), linked in as a static library.

## Rules

- **Three tabs: Home, Browse, Search** (`WorkspaceView`, one `NavigationStack` each, held by `Shell`). Home is what changed, newest first (`cloud_recent`, `RecentModel`); Browse is the workspace as one tree, folders opening in place, in the Mac sidebar's sections (`TreeModel`); Search is `WorkspaceFiles.search` over the sections, names first, then the words of notes. A document pushes over the tab it was opened from, and a link tapped in a note onto that note's stack; a link to a page from outside opens over Home, whatever tab was showing. On an iPad (`.sidebarAdaptable`) Browse's tree sits beside the document.
- **Browse is the sections, each its folder at the top of the workspace**: Library (what everyone has), Restricted, Private, in that order and headed as the Mac's sidebar heads them; the three folders are never rows of their own. Anything else at the top, and a folder with a section's name at the top of Library (`TreeModel.isSectionName`; never made, renamed or moved to there: `WorkspaceFiles.folderNameProblem`), is in no section (`Audience.nowhere`): it stays on this iPhone, and the top's strays show in a group of their own only when there are any. The name is `TreeModel.libraryFolder` (⇄ `LIBRARY_DIR`, engine/src/cloud/space.rs; `LIBRARY_FOLDER`, cloud-worker/src/layout.ts; `LIBRARY_DIR`, src/cloud.ts: **change all four**).
- **New things land in Library**: Browse's New note and New folder, and a move's first choice. A move never offers a folder in no section, and nothing is made at the top. Library, Private and Restricted are never renamed, moved, removed or restricted (`FolderModel.isManaged`).
- **A link opens its page, or waits for it.** `Workspaces.follow` asks the engine which workspace the link is in (`cloud_link_target`): one this device has not joined says how to join; otherwise Home holds the page's place (`arrivingPage`, `ArrivingView`) and asks `cloud_follow_link` again as sync brings files and every few seconds, for `arrivalWait`, then shows the engine's sentence — which never tells a deleted page from one in a folder this person is not in.
- **Who changed something is said in words** (`WhoWords`): a person is their name, this person *You*; an agent is its person's first name and the name they gave it, "Maya’s Research agent" — the whole name when two people share the first, as it stands when it already says whose, "An agent" when the directory no longer has it. The directory is `/api/meta`'s, agents with their `person` (cloud-people-agents.md *Agents*).
- **What was read is the device's own** (`SeenStore`, `seen.json` beside the engine's files): the content address a document's files held when it was last shown, by file id (by path until it has one). Home's dot is a file whose hash differs — or, never read, one changed since the store began, so a phone that just joined does not call everything new. A change of this person's own is never unread. Opened again, what changed since is worked out against the version read (`versions_history`: the manifest's hash is a prefix of the version's), block by block (`ChangeMarks`), and marked. *Remove from this iPhone* forgets it, with what was open in the tree and the recent searches (`UserDefaults`, by `wsId`).
- **Sync speaks only when it needs you.** Its quiet states (`Synced`, `Syncing…`, offline, paused) are a line under the workspace's name on Home; a hold, a question, an error, a notice or a toast rises into the one bar above the tabs (`NeedsYouBar`, `tabViewBottomAccessory(isEnabled:)`, the reason for iOS 26.1). A document hides the tab bar, and its toasts show in its own bar.
- **Reading first; editing in place, with the Mac's own editor.** A document opens to read; *Edit*, or a double tap on a block, makes it editable right there, at that block (`NoteEditing`, `NoteEditor.swift`). The editor is the Mac's Milkdown set-up (`src/ios-editor/`), so the phone writes the markdown the Mac writes: the frontmatter is split off and put back byte for byte (`src/frontmatter.ts`), comments are expanded with their bodies from the meta file and written back as bare markers (`src/metaFile.ts`), and a note whose comments the editor would lose opens to read only. Links to documents are the Mac's too (`src/linkMark.ts`): the editor is handed where the note is and `Workspace.documents`, again whenever they change, and hands back the note with the link records its sidecar is to hold; a relink (a rename while the note is open) is not an edit. Opening writes nothing: a save is measured from what the editor first had. There is no plain-markdown view. The bridge is `window.doklin` there and the `doklin` message handler here (**change both**).
- **A save from the editor writes the sidecar first** (`DocumentModel.save(_:links:over:)`): the sidecar with the records of both texts, then the text, then the sidecar with the new text's records alone (`MetaFile.withLinks`, as the Mac's `sidecarWhileWriting`); everything else in the sidecar is kept as it is. A sidecar that is there but can't be read stops the save before anything is written.
- **The editor reaches nothing.** It is served from the app's own scheme (`doklin-editor://app/`): the editor's files from the app, the note's pictures (`/doc/<path>`) from this iPhone, nothing else; a content rule list blocks every web load. One web view, made after the first frame and kept (`EditorPage.shared`): one note is edited at a time.
- **The phone runs the engine; Swift draws the screens.** Swift calls the engine's commands by name with the Mac frontend's arguments (`Engine.shared.call`, `engine/src/command.rs`) and hears its events; nothing in Swift talks to a domain. What the engine answers is mirrored in `Payloads.swift` (⇄ `engine/src/cloud/status.rs` ⇄ `src/cloud.ts`, **change all three**).
- **A workspace is joined with a line**: `Add a device` on a Mac, or an invite (`cloud_parse_invite` → `cloud_redeem` → `cloud_join`). It is downloaded to `Documents/<name>`; *Remove from this iPhone* is `cloud_leave` (signs out, deletes the copy, nothing changes in the cloud).
- **The sign-in is in the Keychain**, by workspace id (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`): readable while the phone is locked, never in a backup. The engine asks for it through `Host::secrets` (two C callbacks); the phone's `cloud.json` holds `token: ""`. A Keychain that cannot be read just now is never taken for "no sign-in": that workspace waits, untouched (`CloudFile::unread`).
- **Nothing of a workspace is in a backup**: `Application Support/Doklin` (the engine's files, the device id) and `Documents` (the copies) are excluded. A restored phone has nothing, and joins again as a new device.
- **Nothing written here is lost quietly.** A save writes only over what the note held when it was opened (`DocumentModel.save(_:over:)`); a change sync made meanwhile is a choice for the person. *Remove from this iPhone* syncs first and asks again when something has not reached the domain. A line's code works once: a join whose download failed retries with the sign-in it bought.
- **The sync line is the engine's phase, in the Mac's words** (`Limits.swift` ⇄ `syncWords` in `src/cloud.ts`, **change both**). While sync runs (`idle`, `syncing`) the day's limits (`usage.mode`) take over: `bulk-waits` with changes waiting says "412 changes wait until 05:30" (`resumesAt`, local time), with *Send now* (`cloud_lift_wait`) when `usage.liftable`; after a lift, "Sending 412 changes…" while `usage.lifted` and `waiting > 0`; `slow` says sync is slower. A fleet cause has no button: nobody lifts it. `limited` shows the engine's `error` as it stands. `pending-adds` is a notice over the line with *Sync them* / *Not now* (`cloud_confirm_adds`, `sync` true or false), worded from the last `cloud-pending-adds` event.
- **The engine polls the workspace a person is looking at most often**: `woke`, `settle` and a change of workspace tell it `cloud_set_focus {window: "main", folder: <the selected workspace's root, or null>, focused: <the app is active>}`. Nothing polls while iOS has the app suspended.
- **The Cloudflare plan (`usage.plan`) is a row of the workspace's Settings**: read-only, and the superadmin's (`workspace.manage` in `can`) to change, asked first (`cloud_set_plan`). Hidden until the domain has said.
- **Every write is the app's own, then `touched`.** There is no folder watcher on iOS: a file written without `Workspace.wrote` (which rings the engine's edit bus) syncs only at the next poll. `WorkspaceFiles` writes; `Workspace.wrote` tells the engine and every screen.
- **No Trash.** A deletion on the phone — by a person or by sync — is outright; the version store keeps what went (Recently deleted).
- **What a folder holds is the Mac sidebar's rule**: a document is a stem (markdown, html, or both), `<stem>.meta.jsonl` goes wherever its document goes and is never a row, hidden names are `isHiddenOrIgnored` (⇄ `is_hidden_or_ignored` in `engine/src/lib.rs` ⇄ the worker's `IGNORED_NAMES`, **change all three**).
- **Leases are honoured**: a note another device holds opens view-only, with *Take over*; the editor says what it is editing (`cloud_set_activity`), never the reader.
- **What a person may do is the worker's role table** (`CloudStatus.can`, `Workspace.may`); empty means not known yet, and the engine refuses in words.
- **Comments are written as the Mac writes them**: bare markers in the markdown, bodies in `<stem>.meta.jsonl`, byte for byte — sync merges that file by its records with a Mac's (`engine/src/sidecar.rs`). `Comments/` ports `src/criticMarkup.ts`, `src/metaFile.ts` and the worker's placement and html-anchor rules, held to `verify-harness/comments-fixture.json` with the TS (**change both**). Entries are stamped to the second; an emptied meta file is emptied, never deleted. The author is the engine's `device_name`.
- **Rules the Mac's frontend states are ported, not re-invented**, and both sides say so: `timeAgo`/`timeUntil` (`Clock`), `widerAudience` (`Sections.wider`), `mayInviteAgain`, `buildAgentLoginPrompt` (`AgentPrompt`). An address (slug) is checked as the Mac checks it; the engine has the last word.
- **History has no Trash either**: a moment's restore removes what the Mac would move to the Trash, so the moment kept before it is pinned (never thinned) and what went stays under Recently deleted. Recently deleted and the timeline read this iPhone's own stores, since it joined: one per section, Library's first (`stores(of:)`); the workspace's root keeps none, and a restore lands in its store's folder. A note's versions also include what other devices mirrored.
- **A note's links to documents read as the Mac resolves them** (`DocLinks.resolving`, rules: [cloud.md](cloud.md) *Links*): one its sidecar files opens that file wherever it is now, a named link shows the file's name now, and one that opens nothing is greyed and a tap says the engine's one sentence. `DocumentModel.document` is the resolved note, so Find and the marks of what changed read what is shown; it is resolved again whenever `Workspace.documents` (`cloud_documents`) changes.
- **A link to a page opens the app** (rules: [cloud.md](cloud.md) *Links*): from doklin.cc straight, by `applinks:doklin.cc` in `Doklin.entitlements`, or as `doklin://` (`Info.plist`), both through `onOpenURL` → `Workspaces.follow`, whose page the workspace's screens open (`opening`). A tap on one in a note stays in the app (`Workspaces.isPageLink`): one of the note's workspace on this iPhone pushes onto the note's stack (`Workspace.page`), any other goes through `Workspaces.follow`.
- **The engine's sentences say what this device is** (`Setup::device_kind`, `UIDevice.current.model`: iPhone, iPad).
- **Callouts are read as the Mac reads them**: a top-level quote whose first line is `[!NOTE]` (or `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`), alone, any case, is `Block.callout` (`CalloutKind.marker` ⇄ `parseCalloutMarker` in `src/calloutTypes.ts`, **change both**); the reader's box (`CalloutView`) and the editor's (`src/ios-editor/editor.css`) look alike, and so do the reader's headings (`Font.docHeading`) and the editor's.
- **Colours are generated, never typed**: `node scripts/ios-colors.mjs` writes every colour set in `Assets.xcassets` from `src/styles/tokens.css`, for the names `Theme.swift` asks for. `--check` runs in CI.
- **`ios/Doklin/PrivacyInfo.xcprivacy` lists every "required reason" API the app calls, the engine's Rust included** (UserDefaults; file timestamps, which Rust's `stat` counts as): App Store Connect checks each upload's binary against it. A new one (a free-space check, `mach_absolute_time`) is an entry there too.
- **`DoklinKit` imports nothing Apple-only** outside `#if canImport(…)`, so its tests run on Linux. Views go in `ios/Doklin/`; logic a view needs goes in the kit.
- User-facing errors are sentences, here too: the engine answers a refusal as a phrase (`that code doesn't work`), and `Engine` makes it a sentence where it comes in (`DoklinError.sentence`); screens show it as it stands.

## Layout

| Where | What |
| --- | --- |
| `engine/ffi/` | The engine behind three C functions (`include/doklin_engine.h`, **change both** with `src/lib.rs`): start (setup JSON, events, the Keychain callbacks), call a command by name, free |
| `scripts/ios-engine.sh` | Builds `ios/Engine/<platform>/libdoklin_engine_ffi.a` (ignored): `host` for `swift test`, `iphonesimulator`, `iphoneos`. Xcode runs it as the app target's first build phase |
| `ios/DoklinKit/` | Swift package: `Engine/` (`Engine.swift`, `Payloads.swift`), `Models/` (`Workspaces`: the engine's model, join, leave, settle, links; `Workspace`; `WorkspaceFiles`; the screens' models: what changed (`Recent`), what was read (`Seen`), the tree, folder, document, search, people, agents, sections, comments, publishing, history, limits), `Comments/` (the comment format's port), `Markdown/` (the reader's parser, task ticking, links, and `Marks`: what a search found and what changed since a note was read) |
| `ios/Doklin/` | SwiftUI views. UIKit and WebKit only in `NoteEditor.swift` and `PlatformViews.swift` |
| `src/ios-editor/` | The note editor the phone edits in: the Mac's Milkdown set-up without its chrome (`vite.ios-editor.config.ts`) |
| `scripts/ios-editor.sh` | Builds it into `ios/Editor/` (ignored) and, as the app target's last build phase, copies it into the app as `Editor/`. Needs node and `pnpm install`; without node, an editor built before is used |
| `ios/DoklinUITests/` | One class per journey through the real screens (`*UITests.swift`), each joining with a line of its own; run by `drive-ios.mjs --app`, skipped without it. `UITestCase.swift` asks the drive, at the address in `DOKLIN_TEST_DRIVE`, for what only the domain's side can do: `/line` (a device line, minted as the class starts: a person has one code waiting at a time), `/editing?path=` (another device editing), `/deleted?name=` (a restricted folder deleted elsewhere) |
| `ios/Doklin.xcodeproj` | The app and its UI tests. Both folders are synchronized: a file added there is in the build, with no project edit |
| `ios/Info.plist` | Only what build settings cannot say (plain http to a worker on this machine, the `doklin` scheme). The rest is `INFOPLIST_KEY_*` |
| `ios/Doklin.entitlements` | The associated domain links open from. The domain's side is `site/public/.well-known/apple-app-site-association`, which names the app by `DEVELOPMENT_TEAM` and `PRODUCT_BUNDLE_IDENTIFIER` (held to the project by `link.rs`'s tests) |

## Traps

- iOS moves the app's folder on an update: `Setup::anchor` is the container, and everything the engine writes down is relative to it (`engine/src/paths.rs`). The selected workspace is remembered by `wsId`, never by path.
- `cloud_join` answers the folder before the engine has sent that workspace's status: `Workspaces` keeps a just-joined root selected until it does.
- The app gets about thirty seconds when it leaves the screen: `settle` flushes versions and syncs every workspace inside a background task. Nothing syncs while iOS has it suspended.
- `UIDevice.current.name` is the generic model name ("iPhone") without Apple's user-assigned-name entitlement: that is what Devices, presence and comment authors show.
- The bar above the tabs is the tab bar's accessory: a screen that hides the tab bar (a document) hides it too, so a document draws its own toasts. The accessory's content keeps no state of its own (iOS 26.1 drops it on a tab switch): its questions are asked from `WorkspaceView` (`SyncQuestions`).
- WebKit puts its own bar over the keyboard (previous, next, done); the editor's content view is made a subclass of itself without one (`dropInputAccessory`).
- A note's top-level blocks are counted by two parsers, the reader's and Milkdown's: Edit names the block by index and its first words, and the editor finds it by the words when the counts differ.
- `Info.plist` and `Doklin.entitlements` stay outside `ios/Doklin/`: inside the synchronized folder a file is copied as a resource too, and the build fails on two commands producing one file.
- Apple reads the association file from its own cache, refreshed when the app is installed: a change to it reaches phones only once doklin.cc is deployed (`site.yml`, on the push to `main`), and then only on the next install. The archive that first carries the entitlement makes Xcode add *Associated Domains* to the App ID.
- `"\r\n"` is one `Character` in Swift. Lines are split by `MarkdownLines.split`, and a ticked box changes one character in place, so a note's line endings survive.
- A block's `line` is a line of the file, frontmatter included: `togglingTask` takes that number as it is.
- `x-doklin-client` is `ios/<MARKETING_VERSION>`. The version is the project's, not the Mac app's: `bump` does not stamp it, and a push touching only `ios/` cuts no release.
- Diagrams (` ```mermaid `, ` ```svg `) are shown as their source when read; the editor draws them, as the Mac's does.
- The UI tests find rows and fields by `accessibilityIdentifier` (`entry-<name>`, `recent-<name>`, `result-<name>`, `line`, `join`, `edit`, `done`, `workspace-menu`, `workspace-settings`, …), tabs and buttons by their label: renaming either is a change to the tests too. In the editor, the note is the web view's text view.
- iOS 27 changes what the UI tests meet: a button inside a menu's `Section` loses its `accessibilityIdentifier` (a menu's items are found by their label), a confirmation dialog is a popover with no Cancel, drawn wherever iOS puts it (shut with a tap outside it), and a tap on an alert's button just after typing into its field can be lost (`answerAlert` taps again).
- The engine is built for Apple Silicon only. The project excludes `x86_64` from simulator builds (`EXCLUDED_ARCHS`).
- The simulator build must stay signed-to-run-locally for the UI tests: with `CODE_SIGNING_ALLOWED=NO` the app has no Keychain, and a sign-in cannot be kept.

## Building and checking

```sh
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
pnpm install                              # the note editor is built from src/
open ios/Doklin.xcodeproj                 # run (the first build compiles the engine: minutes)
scripts/ios-editor.sh                     # the note editor alone, into ios/Editor/
node verify-harness/drive-ios.mjs         # the core against the harness worker (builds the host engine, runs swift test)
node verify-harness/drive-ios.mjs --app   # the app in a simulator; DOKLIN_ONLY=<class>, DOKLIN_SIMULATOR=<udid>
node scripts/ios-colors.mjs [--check]     # colour sets from tokens.css
```

## TestFlight

The app reaches phones through TestFlight only, never the App Store.

- A build goes up from Xcode: Product → Archive, then Distribute App → App Store Connect, with *Manage Version and Build Number* on. Every upload needs a higher build number than the last, and Xcode takes the next one; nothing in the repository counts them. The same from the command line, with the account Xcode is signed in to: `xcodebuild archive -allowProvisioningUpdates`, then `xcodebuild -exportArchive -allowProvisioningUpdates` with export options `method` app-store-connect, `destination` upload, `manageAppVersionAndBuildNumber` true.
- Archiving needs one device registered to the team, even though nothing is installed from Xcode: automatic signing signs the archive for development first, and Apple makes no development profile for a team with no devices. Xcode registers a connected iPhone only with Developer Mode on; its UDID added under Devices on developer.apple.com does the same without it.
- `MARKETING_VERSION` stays put between builds: testers outside the App Store Connect team see a build only after Apple's beta review, which runs once per version.
- A build expires 90 days after it is uploaded, and the app stops opening: a newer one goes up at least that often.
- Export compliance is answered in the project (`ITSAppUsesNonExemptEncryption = NO`): the app's only encryption is HTTPS to its workers.

To try the app in the simulator with no domain: `node verify-harness/serve-worker.mjs --no-mermaid`, mint a device line with the superadmin token it prints (`drive-ios.mjs` shows how), and paste it.
